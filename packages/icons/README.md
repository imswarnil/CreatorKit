# @creatorkit/icons

55 icons in six sets: `creator`, `media`, `resume`, `social`, `travel`, `ui`.

Drawn on a 24px grid with `stroke="currentColor"` and no intrinsic size, so they take their
colour from the text around them and their size from the kit's icon scale.

## Use

**Sprite** — one request, any number of icons:

```html
<svg class="icon icon-md"><use href="/sprite.svg#ck-rec" /></svg>
```

Copy `dist/sprite.svg` into your public directory, or inline it once at the top of the
page and drop the path from the `href`.

**A single file**, when you only need one:

```html
<img src="@creatorkit/icons/creator/rec.svg" alt="" />
```

**React**, with the name checked at compile time:

```tsx
import type { IconName } from '@creatorkit/icons';
```

## The sets

| Set | What is in it |
| --- | --- |
| `creator` | Record, viewfinder, build log, the things this kit exists for |
| `media` | Play, pause, volume, the player controls |
| `resume` | Role, company, education, the CV vocabulary |
| `social` | The platforms |
| `travel` | Places, transport, weather |
| `ui` | Chevrons, close, search, the everyday |

## Names are unique across sets

The sprite is one id namespace, so two sets cannot both own `sun`. Where they do, the
build qualifies the name with its set — `travel-sun` and `ui-sun` — and says so. Two
different drawings sharing a name is usually an accident; rename one at the source and the
short name comes back.

Everything here is generated by `pnpm build`: `dist/sprite.svg`, `dist/icons.json` and the
`IconName` union in `src/names.ts`. Never edit those; add or rename the `.svg` instead.
