# CreatorKit — instructions for AI assistants

Read `ARCHITECTURE.md` first, and `docs.md` for how the pieces are worked on. It is one page and it contains the only rule that matters:
**one recipe, two renderers.** This file covers the rest.

## What this is

A React + Tailwind UI kit and design system for creators, published at
`creator.imswarnil.com`. It dresses a documentation site, static starter templates, and a
Ghost theme — from one set of component recipes.

## Read this before searching the codebase

Every package carries a generated `INVENTORY.md` listing its components, variants and
files. **Read the inventory before grepping.** It exists so you do not have to open forty
CSS files to answer one question, and it is regenerated by `pnpm build` — never edit it by
hand.

Each package also has its own scoped `CLAUDE.md`. Working inside `packages/broadcast` does
not require loading the Ghost theme's rules; read the local one.

## Hard rules

1. **Dependency direction.** `tokens → core → ui → collections → apps/templates/theme`.
   Never backwards. `tokens` imports nothing.
2. **No hardcoded design values** outside `packages/tokens`. No hex colours, no `px` font
   sizes, no magic durations in `packages/ui`. The build fails on raw hex in `ui` source.
3. **Appearance goes in a recipe**, behaviour goes in the component. A component's classes
   are declared once, in a CVA recipe, and both React and the Ghost theme's CSS are
   generated from it.
4. **Never touch `design.imswarnil.com` or `imswarnil.com`.** They are separate products.
   CreatorKit has no dependency on either, and must not grow one. Do not copy code between
   them without being asked.
5. **`ghost/` is gitignored** and is a preview harness. The theme inside it,
   `ghost/content/themes/creator`, is its own git repository — commit theme changes there,
   not here.
6. **TypeScript strict.** No `any`, no `@ts-expect-error` without a comment saying why.
7. **Accessibility is not a later pass.** Correct roles, keyboard support, focus
   management, visible focus. If a component needs a headless primitive, say so in its
   JSDoc.

## Conventions

- **Commits:** [Conventional Commits](https://www.conventionalcommits.org) —
  `feat(ui): add Dialog`, `fix(tokens): correct dark surface contrast`, `chore: …`.
  One logical change per commit.
- **Class prefix:** generated CSS classes are `ck-` prefixed (`.ck-btn`,
  `.ck-btn--primary`). Tailwind utilities are not prefixed.
- **Component folders:** `Component.tsx`, `component.recipe.ts`, `Component.test.tsx`,
  `Component.stories.tsx`, `index.ts`. Barrel per category, one root `index.ts`.
- **Token names are semantic:** `--ck-color-surface-raised`, never `--gray-100-alt-2`.
- **Package versions** are managed by Changesets. Do not hand-edit a version field.

## Commit hygiene — non-negotiable

No AI attribution anywhere: not in commit messages, pull requests, tags, changelogs,
`CONTRIBUTORS`, or `package.json` author fields. No co-author trailers, no "generated
with" footers, no robot emoji. This is a repository published under a person's name.

## Commands

```bash
pnpm install
pnpm dev          # everything with a dev task, in parallel
pnpm build        # all packages, in dependency order
pnpm lint         # eslint, one config for the workspace
pnpm typecheck
pnpm test
pnpm format
```

Docs site on 3400, Ghost preview on 2370:

```bash
pnpm --filter @creatorkit/docs dev
pnpm ghost:start
```

The Ghost preview is separate and needs Node 22:

```bash
nvm use 22.21.1
cd ghost && ghost start        # http://localhost:2370
```
